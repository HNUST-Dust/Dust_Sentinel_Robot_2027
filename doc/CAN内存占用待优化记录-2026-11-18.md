# CAN 内存占用待优化记录

日期：2026-11-18。

状态：保留问题，暂不调整 CAN 驱动、缓冲容量或设备配置。

## 实际占用

依据本次 `project/build/zephyr/zephyr.elf` 的符号大小和 `zephyr.map`。该构建只启用 EtherCAT 业务线程，但板级 overlay 仍启用 `mcan0`、`mcan1`、`mcan2`，实际 `.config` 中 `CONFIG_CAN=y`，三路 CAN 设备驱动仍被编入。

| 项目 | 内存区域 | 占用 |
| --- | --- | ---: |
| `hpm_mcan_data_0` | 普通 RAM | 4,552 B |
| `hpm_mcan_data_1` | 普通 RAM | 4,552 B |
| `hpm_mcan_data_2` | 普通 RAM | 4,552 B |
| 三路驱动对象合计 | 普通 RAM | **13,656 B** |
| `board_app_mcan_msg_buf` | AHB_SRAM | **20,480 B** |

普通 RAM 和 AHB_SRAM 是两笔独立占用，不应重复计入同一区域。上述对象均为静态分配，设备空闲或停止不会释放；关闭业务线程也不会移除设备驱动对象。

## 普通 RAM：每路按最大过滤器容量预留

驱动对象是每个 CAN 控制器的软件管理结构体 `hpm_mcan_data`，用于保存过滤器、接收回调、发送槽状态、锁、信号量和控制器配置，不是电机对象或业务线程。

源码：`E:/Zephyr_HPMicro/sdk_glue/drivers/can/mcan_hpmicro.c`。

```c
#define HPM_CAN_STD_FILTER_NUM_MAX (128U)
#define HPM_CAN_EXT_FILTER_NUM_MAX (64U)

static struct hpm_mcan_data hpm_mcan_data_##n = {
    .config = DEFAULT_HPM_MCAN_CONFIG,
};
```

每路都固定预留 128 个标准帧过滤器和 64 个扩展帧过滤器，共 192 项；只注册少量 CAN ID 也不会缩小数组。

| 每路成员 | 计算 | 占用 |
| --- | --- | ---: |
| 过滤器配置数组 | 192 × 12 B | 2,304 B |
| 接收回调及参数指针数组 | 192 × (4 + 4) B | 1,536 B |
| 过滤器索引数组 | 192 × 2 B | 384 B |
| 其他配置、锁、信号量、状态及对齐 | 差额 | 328 B |
| 合计 | | **4,552 B** |

过滤器元素类型 `mcan_filter_elem_t` 定义在 `E:/Zephyr_HPMicro/sdk_env/hpm_sdk/drivers/inc/hpm_mcan_drv.h`。以上尺寸对应当前 RV32 构建，不能直接套用到其他 ABI。

## AHB_SRAM：按全部八路控制器预留

同一驱动中的静态数组：

```c
uint32_t board_app_mcan_msg_buf
    [MCAN_SOC_MAX_COUNT][MCAN_MSG_BUF_SIZE_IN_WORDS];
```

HPM5E31 当前 SDK 定义：

- `MCAN_SOC_MAX_COUNT = 8`，位于 `soc/HPM5E00/HPM5E31/hpm_soc_feature.h`。
- `MCAN_MSG_BUF_SIZE_IN_WORDS = 640`，位于 `soc/HPM5E00/HPM5E31/hpm_mcan_soc.h`。

因此占用 `8 × 640 × 4 = 20,480 B`。驱动按芯片全部八路预留，没有按实际启用的三路分配。保持每路容量不变，若仅为三路分配，算术上为 7,680 B，可减少 12,800 B；这只是容量推算，尚未实施或编译验证。

消息 RAM 用于控制器的过滤器、接收 FIFO、接收缓冲和发送缓冲，与普通 RAM 中的软件管理对象用途不同。

## 后续处理边界

1. 先统计各路实际需要的标准帧、扩展帧过滤器数量，再考虑将固定最大容量改为可配置容量。
2. AHB 消息 RAM 考虑按启用设备分配，必须同步处理硬件实例号到消息 RAM 的映射，不能仅缩小数组而继续以原始实例号索引。
3. 每路消息 RAM 是否还能缩小，需核对实际 FIFO、TX/RX Buffer 数量、CAN/CAN FD 数据长度，以及 SDK 的布局和对齐要求。
4. 对仅运行 EtherCAT 的专用配置，可另行评估禁用不用的 CAN 设备；不能因此改变正常机器人配置的 CAN 使用。
5. 若涉及官方 SDK 或 `sdk_glue` 驱动修改，应同步维护 `sdk_glue_user/zephyr-patches` 中的可复现补丁。
6. 实施后需比较新旧 ELF/map，并在目标板验证多路并发收发、过滤器注册和发送完成处理。本记录不代表已完成优化。

本次只记录 CAN 问题，不处理驱动容量，也不将 SII 内存调整混入 CAN 优化结论。
