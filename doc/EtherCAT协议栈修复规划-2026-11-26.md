# EtherCAT 协议栈修复规划

日期：2026-11-26
范围：sentinel（当前工作区，`6424ed7`）+ zephyr_user（`fbe8d2b`）+ midlayer（`eb289d1`）
上位机参考：`temp/Dust_Linux_Architecture-4af5d1e...`，RxPDO 已改为 256 B 平铺，`data[i] = i`

## 0 目标与约束

- 目标：从站能稳定通过 PREOP → SAFEOP → OP，1 ms 收到 RxPDO 并核对 0–255，反馈帧正常上传。
- 约束：不改上位机仓库（只作为参考），所有改动落在当前工作区与两个子树。
- 原则：每一阶段都有可验收的日志，先通 CoE，再通状态机，最后修实时路径。

## 1 阶段划分

### 阶段 1（必须，先让 CoE 稳定）

当前 midlayer `eb289d1` 缺少 `8dab046` 的三项修复，`readPDOmap` 会反复 `ret=0`：

| 缺陷 | 位置 | 修复 |
|---|---|---|
| AL 回 INIT 不停邮箱、不发布 INIT | `midlayer/core/ecat_device.cpp` `ExecuteAlStep` 的 `AlAction::BackToInit` 分支 | 按 OP→SAFEOP→PREOP 逐级 `LeaveOp/LeaveSafeOp/LeavePreOp`，再 `BackToInit()`、`SetState(Init)`、`Publish()` |
| 主站切 PREOP 同拍读 SDO 被拒 | `midlayer/core/model/ecat_dictionary.cpp` `AllowedInCurrentState` 的 `default` | INIT/BOOT 下允许读（按 PREOP 权限），写仍拒绝 |
| 连续 SDO 被静默丢弃 | `midlayer/core/mailbox/ecat_mailbox.cpp` `Service()` | 增加 `if (!send_full_ && receive_locked_) Receive(esc);` |
| SII 偶发只回 4 字节 | `midlayer/core/mailbox/ecat_sii_service.cpp` `HandleRead` | 固定按 8 字节应答 |

验收：主站日志连续多轮 `readPDOmap ret=1 out=2048 in=2048`；从站日志出现完整的 `0x1C00/0x1C12/0x1600/0x1C13/0x1A00` 链。

### 阶段 2（必须，AL 事件串行化）

`EcatDevice::OnPdi()` 和 `EcatDevice::Poll()` 都直接调 `HandleAlEvents()`，ISR 会在 PREOP→SAFEOP 转换中途处理 OP 请求，导致 `0x0011`。

修复：
- `OnPdi`：只 `esc_->ReadAlEvent()` 读走事件并存入 `pending_events_`（`irq_lock` 保护）；
- `Poll`：合并 `pending_events_` 与硬件事件，统一在 1 ms 线程里 `HandleAlEvents()`。

验收：不再出现 `al_state 0x08 failed code=0x0011`。

### 阶段 3（必须，SM 使能/禁用写法和 HAL 访问）

当前 `EnableSyncManagerChannel`/`DisableSyncManagerChannel` 用「读回 dword → 改 PDI 字节 → 写回」，这颗 ESC 偶尔把 0x0804 的控制/状态/使能字节读成 0，写回会把主站配置的控制字节清零（现象：`sm check fail sm2=.../0x01013000 code=0x001d`）。

修复（三选一，推荐 A）：

- **A**：只写 PDI 控制字节 0x0807（1 字节写），不碰 0x0804~0x0806；
- B：整字写 `(pdi << 24) | 0x00010000`（激活位显式带上）；
- C：照 SSC 整字写 0 / `0x01000000`（依赖硬件忽略前三个字节，实测这颗 ESC 有风险）。

配套 HAL 修复（`zephyr_user/zephyr/drivers/ethercat/hal/hpm/ecat_hal_hpm.cpp`）：
- 1 字节写直通 `hpm_esc_write(..., 1)`，不要走非对齐读-改-写；
- ESC 读/写/`ReadAlEvent` 全程加 `k_spinlock`，线程与 PDI/定时中断串行访问。

验收：`sm check fail` 不再出现；`diag station` 全程 `0x1001`。

### 阶段 4（必须，PDRAM 访问）

现象：日志停在 `publish inputs begin`，`EnterSafeOp` 里第一次访问 0x1400 就卡死。

修复（`ecat_hal_hpm.cpp` `EcatEscHpm::Write`）：
- 地址 ≥0x1000、4 字节对齐、长度 4 的倍数 → 按 32 位字逐 4 字节写；
- 或打开 `CONFIG_HPM_ESC_PDRAM_WORD_ACCESS=y`（HPM 官方例程的做法）。

保留 1 字节直通和寄存器区的读-改-写。

验收：`publish inputs begin` 后出现 `publish inputs end`，`safeop event mask set`，最终 `al_state -> 0x04`。

### 阶段 5（收尾）

- 看门狗：`CheckErrors` 只在真正触发退态时打印，避免 `output_disable` 状态下每 1 ms 刷屏；
- 诊断日志：`NoteStation`/`safeop ...` 分步日志保留到 OP 稳定后删除或降为 DBG；
- 上位机侧（不在本仓库，供参考）：请求 OP 前先等 SAFE-OP；状态请求带 ACK 位；`0x0420` 显式写 1000；Recover 加退避；`rx_timeout_us` 临时放大到 20 ms。

| 阶段 | 从站日志 | 主站日志 |
|---|---|---|

## 3 顺序与风险

- 必须按 1→2→3→4 的顺序，前一步没通过时后一步的现象会被掩盖（见《为什么未在当前工作区暴露》）。
- 阶段 3/4 涉及 HAL，改动后先确认其他外设中断没有明显延迟（PDRAM 256 B 字写期间关中断约 50 µs）。
