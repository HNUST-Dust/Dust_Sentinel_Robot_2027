# EtherCAT 0–255 测试图案日志只打印一次调研

日期：2026-11-26
范围：sentinel 从站 `project/thread/ecat/trd_ecat.cpp`（当前工作区，v1 平铺 PdoOutputs）
上位机行为：RxPDO 256 字节按 `data[i] = i`（0–255）填充

## 1 现象

从站日志（节选）：

```
[inf] ecat: al_control=0x04 req=0x04
[inf] ecat: al_state -> 0x04
[inf] ecat: al_control=0x08 req=0x08
[inf] ecat: al_state -> 0x08 (first outputs)
[ok]  ecat: rx pattern 0..255 ok
[inf] ecat rx resumed: state=0x08 sm2=1270
```

之后 `ecat: rx pattern 0..255 ok` 不再出现，而从上位机侧看，从站上传的 TxPDO 数据（`feedback_seq`、遥控轴值、IMU 四元数等）持续变化。

问题：为什么图案日志只打印一次？

## 2 结论

**只打印一次是边缘触发打印的设计结果，不是只收到一帧。**

代码位置：

- `trd_ecat.cpp:80` 定义 `pattern_ok_prev_`（上一次校验结果，初值 false）
- `trd_ecat.cpp:191` 只在出现新 SM2 帧时进入校验：
  ```cpp
  if (sm2_count != last_sm2_count_)
  ```
- `trd_ecat.cpp:196-206` 逐字节核对 `outputs.data[i] == (uint8_t)i`，记录第一个错的偏移和值
- `trd_ecat.cpp:208` 得到本次结果 `pattern_ok`
- `trd_ecat.cpp:210-219` **只有结果变化时**才打印：
  ```cpp
  if (pattern_ok != pattern_ok_prev_) {
      pattern_ok_prev_ = pattern_ok;
      if (pattern_ok) DUST_LOG_OK("ecat: rx pattern 0..255 ok");
      else            DUST_LOG_WRN("ecat: rx pattern mismatch i=%u value=0x%02x", ...);
  }
  ```

所以：

- 首次通过 → 打印一次 `ok`；
- 后续每帧仍然在核对，但只要图案保持正确，`pattern_ok` 与 `pattern_ok_prev_` 相同，不打印；
- 如果图案中途破坏，会打印一次 `mismatch`；恢复后再打印一次 `ok`。

## 3 这份日志能证明什么、不能证明什么

能证明：

- 至少有一帧收到的 256 字节完全等于 0..255；
- 该帧到达时从站处于 OP（`operational == true`）。

不能直接证明：

- 之后每帧都收到（日志不打印 ≠ 没收到，也不 ≠ 没校验）；
- 上位机看到的 TxPDO 变化和 RxPDO 接收无关——TxPDO 是 `FillInputs()` 每 1 ms 生成的反馈帧（`feedback_seq` 自增、遥控/IMU 来自 zbus），两条方向独立。

判断“是否持续有新帧”的量是 `sm2_count`（`slave_.Sm2Count()`，SM2 事件累计计数）。日志里的 `sm2=1270` 是恢复 OP 那一刻的值；后续是否继续增长，需要额外打印或 `log on ecat_cmd` 观察。

## 4 如果需要“持续接收且图案正确”的判据

当前实现只有边沿日志。要证明持续接收，任选一种（均为改动方案，未实施）：

方案 A：周期性打印（推荐）

```cpp
static uint32_t last_pattern_log_ms_ = 0;
...
if (pattern_ok && k_uptime_get_32() - last_pattern_log_ms_ >= 1000u) {
    last_pattern_log_ms_ = k_uptime_get_32();
    DUST_LOG_OK("ecat: rx pattern ok sm2=%u", static_cast<unsigned>(slave_.Sm2Count()));
}
```

方案 B：失败计数

```cpp
static uint32_t pattern_fail_count_ = 0;
if (!pattern_ok) ++pattern_fail_count_;
// 每秒打印一次 pattern_fail_count_ 与当前 sm2_count
```

方案 C：打印判据本身

```
ecat: rx pattern first=0x00 last=0xFF sm2=1270 ok
```

三种都不改变“每帧核对”的逻辑，只是把结论从“仅在变化时”改成“周期性”。

## 5 同段日志里另外两件事

1. 第一次进 OP 失败：

```
al_control=0x04
al_control=0x08
[err] ecat: al_state 0x08 failed code=0x0011
[inf] ecat: al_state -> 0x04
```

`0x0011 = kInvalidAlControl`：上位机在 SAFE-OP 转换完成前就请求 OP，从站当时还在 PreOp，按非法跳转拒绝。之后 `ecat fault saved id=1 code=0x0000`、`rx stopped / rx stalled age_ms=1` 是这次失败的诊断现场。

2. 第二次成功：

```
al_control=0x04 → al_state -> 0x04
al_control=0x08 → al_state -> 0x08 (first outputs)
[ok] rx pattern 0..255 ok
[inf] ecat rx resumed: state=0x08 sm2=1270
```

## 6 后续建议

- 日志行为当前正确，无需修改；若要连续判据，按 §4 方案 A 加一行周期打印即可。
- `0x0011` 属于上位机不等 SAFE-OP 的时序问题；上位机侧在请求 OP 前先等 SAFE-OP（或在从站侧允许 PreOp→Op 自动补一级）可消除。
- 若上位机侧 TxPDO 数据在 OP 后仍在变化，说明反馈路径正常；RxPDO 的持续接收用 §4 的周期判据确认。
