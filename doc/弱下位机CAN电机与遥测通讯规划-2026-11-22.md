# 弱下位机 CAN 电机与遥测通讯规划

日期：2026-11-22。范围：Sentinel 下位机（HPM5E31）与 Linux + SOEM 上位机之间的职责划分，重点回答四件事：

1. CAN 电机反馈数据怎么收、怎么上报；
2. CAN 电机命令怎么下发、怎么执行；
3. 上位机怎么拿到 remote 和 IMU 数据；
4. 用什么通讯模型，端到端延时怎么算、怎么测。

本文是实施规划，不修改代码、配置或上位机，不编译、不烧录、不发送 CAN。

## 1. 范围与既定边界（用户 2026-11-22 口径）

- **控制逻辑上移上位机**：底盘运动学、速度环、摩擦/惯量前馈、yaw 协同、pitch 目标平滑/角环/重力补偿，全部在上位机计算。
- **IMU 和 remote 不上移**：采样、解析、标定、失联判定、加热控温、姿态解算仍在下位机；下位机把结果打包上报，上位机只消费。
- **下位机保留**：CAN 收发与反馈解析、设备状态机、限幅/限位、失联保护、停机执行、急停否决。
- **单一输出所有者**：任一电机同一时刻只能由 LOCAL 或 HOST 一方计算正常输出；切换先停机，不做带负载热切换。
- 本文取代 [弱下位机与EtherCAT控制上移规划](弱下位机与EtherCAT控制上移规划-2026-11-18.md) 中 P6"姿态算法上移"的选项：本次不迁 IMU EKF，也不迁遥控业务映射。

## 2. 现状核对（代码事实）

| 对象 | 现状 | 位置 |
| --- | --- | --- |
| EtherCAT | 双向各 64 × uint32_t = 256 B；PDO 目前是计数测试数据 + 导航包前段 | [trd_ecat.cpp](../project/thread/ecat/trd_ecat.cpp)、[trd_ecat.hpp](../project/thread/ecat/trd_ecat.hpp) |
| CAN TX | 单线程 `k_poll` 等 CAN0/CAN1 两条 FIFO，按就绪事件排空发送，每帧 `Send(..., K_MSEC(1))` | [trd_can_tx.cpp](../project/thread/can/trd_can_tx.cpp) |
| CAN 发送队列 | `user_can0_msgq` / `user_can1_msgq`，各 16 槽，消息 `{tx_id, version, data[8]}` | `framework/topic/to_can_tx` |
| 底盘 | C620×4 在 CAN1；速度环/前馈/逆运动学在 `Task()` 内，直接 `PackCurrent` 进 `0x200` 帧 | [trd_chassis.cpp](../project/thread/chassis/trd_chassis.cpp) |
| 云台 | 大 yaw CAN1、小 yaw/pitch CAN0 均为达妙 MIT；控制环在各自 `trd_*` 内 | [trd_yaw.cpp](../project/thread/gimbal/yaw/trd_yaw.cpp)、[trd_pitch.cpp](../project/thread/gimbal/pitch/trd_pitch.cpp) |
| 电机反馈 | `CAN_RX_HANDLER` 注册在各自 trd 里，回调进 `CanCpltRxCallback`，seqlock 快照可读 | `framework/modules/motors/{dji,dm}` |
| remote | `topic::remote_to::Message`：`version` + 4 轴归一化 + 模式/自定义开关 | `framework/topic/remote_to` |
| IMU | `topic::imu_to::Message`：`version` + 四元数 + gyro/accel + 温度 + roll/pitch/yaw/yaw_total | `framework/topic/imu_to` |

关键缺口：

- 两路话题都**没有接收/采样时间戳**，只有帧序号；`age` 只能在上报侧另补。
- 电机驱动 `Snapshot` 是 seqlock 一致快照，但**不暴露帧序号和接收时刻**。
- CAN 反馈回调与电机实例绑在控制线程文件里，关闭控制线程会一起丢反馈——必须先把硬件装配拆出来。

## 3. 通讯模型

### 3.1 结论：EtherCAT 周期 PDO 承载控制与遥测，CoE SDO 只做诊断

| 用途 | 通道 | 理由 |
| --- | --- | --- |
| 1 ms 周期遥测（remote/IMU/8 路电机反馈/状态） | TxPDO，256 B | 已有 SOEM 主站、链路已验证；周期确定、无需额外协议栈 |
| 1 ms 周期命令（8 路电机执行量 + 会话/租约） | RxPDO，256 B | 同周期收发，一拍出错可被租约兜底 |
| 使能/失能/清错/设零等离散操作 | RxPDO `DeviceOperation` 槽 | 需要序号去重和应答，不适合塞进周期字段后不管 |
| 参数、温度、错误码、日志等低频诊断 | CoE SDO / 管理服务（后续） | 不挤占周期带宽，不改变周期布局 |
| 原始 CAN 帧透传 | **不采用** | 会把输出保护、编码和时序责任推给上位机，违背"下位机保留执行保护" |

不采用 USB 串口 / 自定义 UDP 作为控制通道：现有主站和从站已经把 EtherCAT 链路跑起来了，再引入第二条控制链路会多一套时钟、握手和故障恢复。

### 3.2 周期与方向

- 主站周期目标 **1 ms**，用 `CLOCK_MONOTONIC` 绝对时间等待（`clock_nanosleep` + `TIMER_ABSTIME`），迟到记超期、跳过失效时隙，不补发旧命令。
- 从站 PDI ISR 锁存 RxPDO，1 ms 线程侧组帧 TxPDO；两者之间用"快照复制 + 序号"，不跨上下文传指针。
- 所有命令带 `command_seq`，只有上位机产生新决策时才自增；重复发送同一命令不能续租。
- 命令带 `lease_us`（MCU 本地上限，初始候选 10 ms），按"被引用反馈的 MCU 时刻 + lease"计算 deadline，迟到包不会重新变新。

## 4. 数据面：两帧 256 B 布局

沿用既有草案，首版冻结后作为上下位机共用协议头实现；实现时禁止把 Zephyr `topic::Message` 直接 `memcpy` 上线，必须显式字节编解码。

### 4.1 TxPDO：下位机 → 上位机

| 偏移 | 内容 | 字节 |
| ---: | --- | ---: |
| 0 | `FeedbackHeader` | 40 |
| 40 | `RemoteFeedback` | 32 |
| 72 | `ImuFeedback` | 56 |
| 128 | `MotorFeedback[8]`，每槽 16 B | 128 |
| | 合计 | **256** |

- `FeedbackHeader`：magic、协议主/次版本、`mcu_boot_id`、`feedback_seq`、`mcu_tick_us`、`applied_command_seq`、`accepted_host_session`、`operation_ack_seq`、`status_flags`、`fault_code`、`armed_mask/can_health`。
- `RemoteFeedback`：`source_seq` + `sample_tick_us` + `axis[4]`（chassisx/chassisy/yaw/pitch 归一化）+ `controls`（开关位）+ `status`（协议类型/有效性/丢帧）。
- `ImuFeedback`：`source_seq` + `sample_tick_us` + `quaternion[4]` + `gyro[3]` + `accel[3]` + `temperature` + `flags`（姿态有效位由下位机给，不伪造）。
- `MotorFeedback`：`position(f32)` + `omega(f32)` + `effort_feedback(f32)` + `age_ms(u16)` + `flags(u16)`；DJI 的 effort 单位 A，达妙单位 N·m，按槽位类型区分。

### 4.2 RxPDO：上位机 → 下位机

| 偏移 | 内容 | 字节 |
| ---: | --- | ---: |
| 0 | `CommandHeader` | 48 |
| 48 | `MotorCommand[8]`，每槽 16 B | 128 |
| 176 | `DeviceOperation` | 32 |
| 208 | `DiagnosticRequest` | 16 |
| 224 | 保留（全零） | 32 |
| | 合计 | **256** |

- `CommandHeader`：magic、版本、`byte_length`、`slot_map_version`、`host_session`、`command_seq`、`mcu_boot_id_echo`、`feedback_seq_echo`、`lease_us`、`compute_time_us`、`flags`（arm/disarm 请求）、`enable_mask`、保留。
- `MotorCommand`：`slot(u8)` + `effort_kind(u8)` + `flags(u16)` + `effort(f32)` + 保留 `[2](u32)`；`effort_kind` 只允许该槽配置的 `CURRENT_A` 或 `TORQUE_NM`，不符整槽拒绝。
- `DeviceOperation`：`operation_seq` + `opcode`（ENABLE/DISABLE/CLEAR_FAULT/SAVE_ZERO）+ `target_slot` + `payload[20]` + `flags`；每个 `operation_seq` 最多执行一次。

### 4.3 八槽固定映射（首版）

| 槽 | 设备 | 总线 | 反馈 ID | 控制 ID | 指令单位 |
| ---: | --- | --- | --- | --- | --- |
| 0–3 | 底盘轮 C620 | CAN1 | 0x201–0x204 | 共享 0x200 | A |
| 4 | 大 yaw 达妙 | CAN1 | 0x11 | 0x01 | N·m |
| 5 | 小 yaw 达妙 | CAN0 | 0x13 | 0x03 | N·m |
| 6 | 上 pitch 达妙 | CAN0 | 0x14 | 0x04 | N·m |
| 7 | 下 pitch 达妙 | CAN0 | 0x12 | 0x02 | N·m |

槽位表带版本号；换槽=升级协议，不允许长度不变时悄悄调换。方向以电机原生正方向为准，符号转换在上位机设备适配层完成一次；下位机不再重复取反。

## 5. CAN 电机接收数据怎么处理

### 5.1 收包路径（保留在 ISR）

```text
CAN 控制器 RX FIFO → Can::rx_callback（ISR）
  → CAN_RX_HANDLER 按 ID 分发 → 电机驱动 CanCpltRxCallback
  → seqlock 写 Snapshot（位置/速度/电流/力矩/温度/错误）
  → 记录 last_rx_tick_us、rx_seq、online 标志
```

- 现有 `CAN_RX_HANDLER` + `CanCpltRxCallback` 机制保留，不在 ISR 里做任何业务计算。
- 每个槽额外记录**接收时刻**和**帧计数**：时间用 `k_cycle_get_64()` 换算 µs，`age_ms` 由"当前时刻 − 最后接收时刻"饱和到 65535，禁止溢出回零。
- 在线判定用"最近一次有效帧的 age"，不用"读到一个旧对象"。

### 5.2 装配位置（必须先拆）

把以下内容从 `trd_chassis.cpp` / `trd_yaw.cpp` / `trd_pitch.cpp` 移到独立的硬件装配模块（建议 `modules/robot_hardware/`）：

- 电机实例、`Config`（CAN ID、类型、量程、方向、减速比）；
- `CAN_RX_HANDLER` 注册；
- 每个槽的接收时间/序号包装；
- 设备健康摘要（bus-off、错误计数、在线位）。

这样关闭任何本地控制线程，反馈采集和上报都不受影响。

### 5.3 上报路径

1. 1 ms 周期线程（EtherCAT 线程或独立采集汇总）读 8 路快照 + 时间戳；
2. 组装 `MotorFeedback[8]` 与 `RemoteFeedback`/`ImuFeedback`；
3. 写 TxPDO 值成员，ISR 在下一拍锁存发送。

不做"每帧 CAN 反馈都单独上报"：1 kHz 反馈在 1 ms PDO 里按槽上报最新快照即可；中间样本丢失由 `age_ms` 和序号体现，不用伪造连续性。若后续上位机 EKF 需要不丢样本，另立"多样本批量协议"，不在本版偷偷加长帧。

## 6. CAN 电机命令怎么下发与执行

### 6.1 执行器职责（`modules/motor_executor/`）

所有正常输出和停机输出都经过同一个执行器，旧控制线程不得再旁路 `PackCurrent` / `PackCtrlFrame` / 直接 `k_msgq_put`。

执行器每 1 ms 一拍：

1. 解码 RxPDO（校验 magic/版本/长度/槽位/类型/有限值）；
2. 检查会话、`command_seq`、`feedback_seq_echo` 年龄、`lease_us` 是否过期；
3. 检查本地否决：遥控关闭/failsafe、CAN 健康、设备错误、机械限位；
4. 对每个槽做本地限幅（C620 ±20 A、达妙 TMAX 等来自本地配置，主站不能提高）；
5. 按槽编码：
   - C620：四个槽填进 `0x200` 帧大端 int16，固定 1 kHz 从 CAN1 发出；
   - 达妙：MIT 帧，kp=kd=0，只写力矩字段，每槽各自 ID 1 kHz 发出；
6. 记录 `applied_command_seq`、发送成功/失败计数、限幅/拒绝原因。

### 6.2 周期值 vs 离散操作

| 类型 | 处理 |
| --- | --- |
| 周期电流/力矩 | **最新值槽位**：每槽只保留最新一条，新命令覆盖旧命令；不做无界 FIFO，不让几十帧旧力矩排在停机命令前面 |
| 使能/失能/清错/设零 | 有界状态机：收到 new `operation_seq` → 执行 → 发应答 → 记录 `operation_ack_seq`；同序号重发不重复执行 |
| 停机 | 优先级最高：租约过期/失联/掉 OP 时立即用停机帧覆盖待发值；C620 发零电流帧，达妙按第 6.4 节策略处理 |

### 6.3 新鲜度与租约

- `command_seq` 不推进 = 控制算法停更 → 租约到期后本地停机，不能靠重复发送同一帧续命。
- `feedback_seq_echo` 指向本命令依据的反馈；MCU 检查该反馈的打包时刻是否在窗口内，超出窗口或 `boot_id` 不符 → 拒收。
- 主站时间只用于自身调度和日志；没有时间同步前，不用 host 时间戳当 MCU 绝对 deadline。MCU µs 计数约 71.6 分钟回绕，所有比较用模差。

### 6.4 停机动作（分轴确认）

- C620：零电流帧即可（电调内部闭环）。
- yaw：零力矩可接受；保留本地机械限位。
- pitch 带重力负载：零力矩可能下落。**停机策略必须逐轴确认**（支撑、机械制动、驱动器本地停车或保留独立的安全力矩控制），未确认前不把"发零"当整机安全姿态。此项是带负载验证前的放行条件。

## 7. 上位机如何拿到 remote 和 IMU

### 7.1 数据流

```text
MCU remote 线程（解析/映射/失联判定）→ remote_to 话题（MCU 内部）
MCU IMU 线程（采样/标定/EKF/加热）    → imu_to 话题（MCU 内部）
        ↓ 1 ms 汇总线程取最新快照 + 打本地采样时刻
TxPDO RemoteFeedback / ImuFeedback（各带 source_seq + sample_tick_us）
        ↓ EtherCAT
上位机 1 ms 周期线程：原始字节 → 带时效的设备快照
        ↓
上位机控制模块（纯函数：Snapshot + Target + dt → Effort）
```

### 7.2 时间语义

- `sample_tick_us` 必须是**采样/接收动作发生时的 MCU 本地时刻**，不能用"打包 PDO 的时刻"冒充。
- `source_seq` 来自话题 `version`（每帧自增）；上位机用序号推进判断数据是否仍在更新，用 age 判断是否过期。
- 上位机不重复减 IMU 静态偏置、不重复做安装轴变换：这些固定进协议/能力版本，由下位机完成一次。
- remote 的 `controls` 位先保持现有 DR16/SBUS 映射的语义等价，避免迁移同时改业务定义；后续若彻底上移模式映射，升级协议版本。

### 7.3 频率不一致的处理

- IMU 与 remote 按各自频率采样，PDO 只带最新值；上位机控制若用"最新样本 × 固定 dt"会丢积分信息。
- 首版上位机控制按实测 age 使用最新姿态，接受丢中间样本；姿态影子/预积分方案另立任务，不在本版偷偷实现。

## 8. 延时与测量

### 8.1 端到端链路

```text
传感器/CAN 采样 → MCU 快照 → TxPDO 锁存 → EtherCAT 传输
 → 主站收包 → 上位机计算 → RxPDO 发送 → MCU PDI 锁存
 → 执行器接纳 → CAN 排队/发送 → 电调接收
```

### 8.2 预算（初始候选，未实机标定）

| 环节 | 候选值 |
| --- | --- |
| MCU 采样 → TxPDO 锁存 | ≤ 1.2 ms（1 ms 周期 + ISR 抖动） |
| EtherCAT 单向传输 | 0.1–0.5 ms |
| 上位机接收 + 控制计算 | ≤ 0.5 ms |
| RxPDO → 执行器接纳 | ≤ 1 ms |
| CAN 8 B 帧 @1 Mbps（含仲裁/填充） | ≈ 0.12–0.15 ms |
| 电调内部响应 | ≈ 1 ms 量级 |
| **合计典型值** | **约 3–5 ms** |
| **设计目标（反馈→命令发出）** | 典型 ≤ 6 ms，最坏 ≤ 10 ms |

这些是开始台架测试的候选值，不是实机安全标定；每项必须实测后冻结。

### 8.3 已知抖源

- MCU EtherCAT 线程 1 ms 周期、CAN 执行器 1 ms 周期、SM 同步相位：可能叠加 1–2 拍。
- 主站 Linux 调度、网卡 IRQ、`clock_nanosleep` 迟到：必须记录超期分布，不能只看平均值。
- CAN 总线负载：CAN1 同时有 4 个 C620 反馈 + 大 yaw，按 1 kHz 估算占用已较高（见 [弱下位机与EtherCAT控制上移规划](弱下位机与EtherCAT控制上移规划-2026-11-18.md) §8.3），不要因为主站能跑更快就把 CAN 速率翻倍。
- 单线程 CAN 执行器：CAN1 的 `Send()` 等待会推迟 CAN0，反之亦然；必须测"一路等待较长时另一路的附加延迟"。

### 8.4 测量方法

- MCU：GPIO 翻转标记"快照读取 / 命令接纳 / CAN 提交"三个时刻，示波器或逻辑分析仪测；日志里带本地 µs 时间戳。
- 主站：记录收发间隔、WKC、AL 状态、`feedback_seq`/`command_seq` 年龄、超期次数。
- 跨机：用同一次 GPIO 事件或抓包对齐，不直接相减两台机器的单调时钟。
- 报告至少给：平均值、P99、最大值、连续丢帧次数。

## 9. 模块落点与线程划分

| 落点 | 职责 |
| --- | --- |
| `project/thread/ecat/` | EtherCAT 生命周期、PDO 编解码、通信诊断；不计算机器人 PID |
| `modules/robot_hardware/` | 八槽设备装配、CAN ID/类型/量程、CAN RX 注册、反馈时间戳 |
| `modules/io_bridge/` | remote/IMU 快照 → TxPDO 字段；反馈 → 带时效快照 |
| `modules/motor_executor/` | 唯一执行器、限幅/限位、租约、设备状态机、CAN0/CAN1 有界调度 |
| 协议目录（共用） | wire 定义、版本、编解码、黄金报文；无 Zephyr/SOEM 依赖 |
| 旧 `trd_chassis` / `trd_yaw` / `trd_pitch` | 迁移期保留为影子对照，接管后关闭正常输出 |

线程：

- `ecat`：1 ms，High，负责 PDO 编解码与通信状态；
- `motor_exec`：1 ms（或由 SM2 事件驱动），High，负责编码发送与保护；
- `can_tx`：现有合并线程保留为"发送通道"，执行器只向它提交组好的帧；不恢复双线程；
- remote/IMU 线程不动。

## 10. 实施阶段

> 执行规则：用户说"开始第 N 步"= 只改该步点名文件，改完停下等"继续"；每阶段结束给出"静态检查/编译/实机"分别完成到哪里。

## 11. 验收矩阵

| 场景 | 必须看到的结果 |
| --- | --- |
| 只有重复 PDO，控制算法停更 | `command_seq` 不推进，租约到期本地停机 |
| 反馈重复读取但源数据停更 | `age_ms` 持续增长，受影响控制不使用旧反馈 |
| 主站退出/拔网线/掉 OP | 不迟于本地期限执行停机；记录 CAN 真正发出时刻 |
| 重新连通 | 不自动恢复旧输出；新会话 + 零命令 + 显式 arm 后才运行 |
| 非法槽位/NaN/Inf/错误类型/旧会话 | 拒绝并记录原因，不刷新租约 |
| 遥控关闭/failsafe | MCU 本地否决，不依赖上位机 |
| CAN bus-off/发送失败 | 不报告"已执行成功"；失败可观测 |
| yaw ±π、大小轴分配 | 世界参考连续，不重复取反 |
| pitch 带负载停机 | 按确认后的停机策略执行，不自由下落 |

## 12. 待确认（实施前必须由用户拍板）

1. 上位机仓库路径与实际接口（SOEM 版本、IOmap 结构）。
2. 八槽映射与每路 CAN 实际帧率是否与源码一致。
3. 命令租约上限（候选 10 ms）与 IMU/遥控/电机反馈的新鲜度阈值。
4. pitch 带负载停机方式（支撑/制动/驱动器停车/独立安全控制）。
5. 姿态是否长期留在下位机（本文按"留"执行）。
6. v1 协议是否允许直接替换当前 256 B 计数测试 PDO。
